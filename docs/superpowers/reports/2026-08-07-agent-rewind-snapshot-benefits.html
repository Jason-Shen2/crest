Safety invariant

保留的能力

共享捕获层，没有削弱回退的安全底座。

这次变化只替换 snapshot 的物理获取方式。checkpoint、磁盘冲突检测、workspace lock、confirmation token 和 fail-closed 仍保持原语义。

A

多 Session，共享 tracker

同一物理 workspace 只建立一个 baseline；Session 仍各自持有 checkpoint 和消息树。

B

精确 before / after

Undo 继续应用 checkpoint.after → checkpoint.before，不依赖 write/edit 工具调用历史。

C

外部写入必须冲突

磁盘状态与 checkpoint 不一致时，普通 revert 停止；只有显式 Force 可以覆盖确认的文件。

D

观察不连续时 fail closed

watcher gap、scope invalidation 或 capture budget 不会生成“available empty”的假 checkpoint。

Engineering conclusion

这次优化消除了重复全仓扫描；还没有消除首次建库成本。

对日常无改动 turn 和多 Session 并行，这是结构性改进：工作量不再与 workspace 总文件数 × Session 数量线性相乘。但对大型 monorepo，cold baseline 与大量 dirty paths 仍可能接近生产 deadline。下一步应优化 full snapshot 对象持久化和 anchored path capture，而不是继续堆叠 Session 级缓存。
