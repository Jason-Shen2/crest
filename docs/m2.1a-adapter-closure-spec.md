# M2.1A Pi GUI Adapter Closure Specification

## Status

Design complete. This document defines the implementation boundary for M2.1A and is the source of truth for `docs/m2.1a-adapter-closure-subagent-plan.md`.

## Goal

Close the semantic adapter layer for every standard vendored `pi-tui` component so Crest can identify, snapshot, traverse, dispatch to, and dispose those components through explicit public contracts rather than `constructor.name`, private-field reads, or shape heuristics.

M2.1A is complete when:

- every standard component kind is represented by a real `PiGuiAdapter`;
- every adapter reads a public immutable snapshot;
- nested standard components are traversed through adapter-owned child discovery;
- interactive standard components are dispatched only through their adapter;
- unsupported custom components retain the current debug terminal fallback without being mistaken for standard components;
- adapter contract, bridge routing, certification, and regression tests pass.

## Context

M2.1B established `AgentSessionRuntime` as the owner of recoverable extension UI state and made reload/disposal deterministic. The remaining adapter-layer gaps are independent of that lifecycle work:

- `getPiGuiAdapters()` advertises eleven kinds but only five are wired;
- `Text`, `Box`, `Spacer`, `Markdown`, `Image`, and `TruncatedText` are serialized in `walker.ts` by reading implementation fields;
- `walker.ts` accepts `constructor.name` matches for standard and rich components;
- the adapters for `Input`, `SelectList`, `SettingsList`, `Editor`, and `Loader` use method-shape probing as a secondary identity mechanism;
- `bridge.ts` reads `children` directly and contains a generic event fallback that can treat arbitrary lookalikes as standard interactive components;
- `CancellableLoader` cancellation reads `aborted` and invokes `handleInput()` through casts instead of a dedicated public adapter contract.

These gaps make upstream drift silent: a renamed private field can produce an incomplete widget instead of a type error or focused contract-test failure.

## Scope

### In Scope

- A stable runtime component-kind marker shared by standard vendored components and Crest adapters.
- Public snapshot interfaces and `getSnapshot()` methods for presentational standard components.
- Snapshot completion for `Loader` and `CancellableLoader`.
- Real adapters for:
  - `Text`
  - `Box`
  - `Spacer`
  - `SelectList`
  - `SettingsList`
  - `Input`
  - `Markdown`
  - `Editor`
  - `Image`
  - `Loader`
  - `CancellableLoader`
  - `TruncatedText`
- Adapter-owned child discovery for `Box`.
- WeakMap-owned widget identity that never mutates component instances.
- Removal of standard-component serialization from `walker.ts`.
- Removal of standard-component shape dispatch from `bridge.ts`.
- Focused tests proving that renamed constructors still work through the explicit marker and unmarked lookalikes fall back to `terminal`.
- Compatibility evidence updates and an M2.1A status record in `docs/pi-gui-design.md`.

### Out of Scope

- M2.1C behavior closure: IME, clipboard, selection, search, submenu, scrolling, focus, editor cancel, and loader cadence certification.
- Changing React widget appearance or interaction behavior.
- M3 terminal-surface fallback for arbitrary custom components.
- Replacing Crest rich components (`RichTable`, `DiffView`, `Chart`) with Pi standard adapters.
- Extension lifecycle, session replay, reload handoff, or request cancellation changes completed by M2.1B.
- Generated files, package dependencies, Electron IPC shapes, and persistence formats.

## Contract Design

### Stable Component Identity

`emain/agent/extensions/pi-gui/src/tui.ts` will export one global-symbol marker and a closed standard-kind union:

```ts
export const PiGuiComponentKind = Symbol.for("crest.pi-gui.component-kind");

export type PiGuiComponentKind =
    | "text"
    | "box"
    | "spacer"
    | "selectlist"
    | "settingslist"
    | "input"
    | "markdown"
    | "editor"
    | "image"
    | "loader"
    | "cancellableloader"
    | "truncatedtext";

export interface PiGuiComponent<K extends PiGuiComponentKind = PiGuiComponentKind> extends Component {
    readonly [PiGuiComponentKind]: K;
}

export function hasPiGuiComponentKind<K extends PiGuiComponentKind>(
    component: Component,
    kind: K
): component is PiGuiComponent<K> {
    return (component as Partial<PiGuiComponent>)[PiGuiComponentKind] === kind;
}
```

`Symbol.for` is required rather than a module-local `Symbol()` so the marker remains stable when extension fixtures and the host resolve the vendored module through separate loader paths. The marker is an explicit protocol, not an inferred class name.

Each standard component class declares a marker whose runtime value is a kind literal and whose property type is the closed union. The widened property type is required because `Loader` inherits `Text` and `CancellableLoader` inherits `Loader`:

```ts
readonly [PiGuiComponentKind]: PiGuiComponentKind = "input";
```

`Loader` overrides the inherited text marker with `"loader"`, and `CancellableLoader` overrides it again with `"cancellableloader"`.

### Public Snapshots

Snapshot methods return semantic data only. They do not expose themes, cache state, timers, callbacks, terminal objects, or mutable internal arrays.

| Component | Public snapshot fields |
| --- | --- |
| `Text` | `text`, `paddingX`, `paddingY` |
| `Box` | `children`, `paddingX`, `paddingY` |
| `Spacer` | `lines` |
| `SelectList` | existing `items`, `selectedIndex`, `maxVisible`, `focused`, `filter` |
| `SettingsList` | existing `items`, `selectedIndex`, `maxVisible`, `filter` |
| `Input` | existing `value`, `cursor`, `focused` |
| `Markdown` | `source`, `paddingX`, `paddingY` |
| `Editor` | existing `value`, `lines`, `cursorLine`, `cursorCol`, `focused`, `paddingX` |
| `Image` | `base64Data`, `mimeType`, `filename`, `widthPx`, `heightPx` |
| `Loader` | `label`, `frame`, `cancellable: false`, `aborted: undefined` |
| `CancellableLoader` | `label`, `frame`, `cancellable: true`, `aborted` |
| `TruncatedText` | `text`, `paddingX`, `paddingY` |

Array-bearing snapshots must return fresh arrays:

- `BoxSnapshot.children` returns `[...this.children]`;
- existing item snapshots continue returning copied item arrays;
- `EditorSnapshot.lines` remains copied by the adapter before entering the widget tree.

The image snapshot exposes the original base64 and metadata because the GUI widget must construct a data URL. It does not expose `imageId`, terminal capabilities, or renderer cache state.

### Adapter Interface

The adapter contract gains optional child discovery:

```ts
export interface PiGuiAdapter<TComponent extends Component = Component> {
    kind: PiGuiComponentKind;
    matches(component: Component): component is TComponent;
    snapshot(component: TComponent, context: SnapshotContext): WidgetNode;
    dispatch(component: TComponent, event: WidgetEvent, context: DispatchContext): DispatchResult;
    children?(component: TComponent): readonly Component[];
    dispose?(component: TComponent): void;
}
```

Rules:

- `kind` is a closed `PiGuiComponentKind`, not an arbitrary string.
- `matches()` checks only the explicit marker for standard components.
- every listed kind has a concrete adapter object; adapter enumeration does not synthesize unwired entries.
- presentational adapters return `{ handled: false }` for every event.
- `BoxAdapter.children()` returns the copied child list from `Box.getSnapshot()`.
- `LoaderAdapter` and `CancellableLoaderAdapter` share node serialization but have separate identity and cancellation rules.
- only loader adapters implement `dispose()`.

### Walker

`componentToWidget()` follows this order:

1. Find a standard adapter and return its snapshot.
2. Recognize Crest-owned rich components by direct `instanceof` checks and call `toWidget()`.
3. Render every other component as the existing `terminal` debug node.

The walker will contain no standard-component imports, field readers, `constructor.name` logic, or standard-kind switch.

### Widget Identity

`walker.ts` must not attach Crest metadata to vendored or extension-owned component objects. Replace the current `__crestwidgetid` expando property with module-owned weak identity:

```ts
let nextWidgetId = 0;
const WidgetIds = new WeakMap<Component, string>();

function makeId(component: Component, prefix: string): string {
    const existing = WidgetIds.get(component);
    if (existing) return existing;
    nextWidgetId++;
    const id = `${prefix}-${nextWidgetId}`;
    WidgetIds.set(component, id);
    return id;
}
```

Identity rules:

- repeated snapshots of the same live component return the same ID;
- distinct component objects receive distinct IDs;
- the first successful snapshot fixes the prefix for that component;
- frozen, sealed, and non-extensible components serialize without mutation;
- unreachable components may be garbage-collected because the registry is a `WeakMap`;
- IDs are process-local renderer protocol identifiers and are not persisted or restored across process restarts.

### Nested Target Registration

`bridge.ts` registers child widget targets by asking the root component's adapter for children:

```ts
function getComponentChildren(component: Component): readonly Component[] {
    return getPiGuiAdapter(component)?.children?.(component) ?? [];
}
```

Child widget nodes and child components remain paired by index. A mismatch registers only the common prefix, preserving the current defensive behavior.

### Event Dispatch

For standard components:

1. Resolve the live target by `nodeid`.
2. Resolve its adapter.
3. Normalize a record payload.
4. Call `adapter.dispatch()`.
5. Rerender only when `handled` is true.
6. Preserve the existing `done(undefined)` handling for an unhandled custom-dialog cancellation.

The generic fallback remains only for unknown terminal nodes:

- a `key` event may call a custom component's public `handleInput(data)` method;
- a `cancel` event may settle `target.done(undefined)`;
- `change`, `submit`, and `select` never probe arbitrary methods.

This preserves the current debug fallback without allowing unmarked lookalikes to impersonate standard components.

## Failure Semantics

- An unmarked object whose constructor is named like a standard component is not adapted.
- A marked standard component with a broken public snapshot fails in focused adapter tests and may throw at the call site; the adapter must not silently read alternate fields.
- Invalid event payloads return `{ handled: false }` and do not mutate component state.
- Presentational components reject all events.
- A plain `Loader` rejects cancel.
- A `CancellableLoader` cancel calls its public cancellation method and returns handled.
- Disposing either loader is idempotent through `stop()`/`dispose()`.
- Unknown custom components continue to produce a `terminal` node.

## Test Strategy

### Component Contract Tests

Tests instantiate every standard component and assert:

- the exact marker kind;
- exact public snapshot content;
- copied array isolation for `Box`;
- distinct loader/cancellable-loader snapshots;
- snapshot updates after public setters.

### Adapter Tests

Tests assert:

- adapter enumeration contains every concrete kind exactly once;
- every standard instance resolves to the expected adapter;
- no adapter resolves unmarked constructor-name or method-shape lookalikes;
- every adapter produces the expected widget node;
- presentational adapters reject events;
- interactive adapters retain existing dispatch behavior;
- loader disposal and cancellable cancellation use public methods.

### Walker Tests

Tests assert:

- standard widgets serialize without calling `render()`;
- `Box` children preserve order and stable IDs;
- frozen components serialize successfully, retain no `__crestwidgetid` own property, and keep a stable ID across repeated snapshots;
- distinct components receive distinct WeakMap-owned IDs;
- constructor renaming does not affect marked components;
- unmarked lookalikes and unknown custom components fall back to terminal output;
- rich Crest components continue to serialize through `toWidget()`.

### Bridge Tests

Tests assert:

- nested `Box` events reach the matching child via adapter child discovery;
- unmarked lookalikes cannot receive `change`, `submit`, or `select`;
- unknown custom components still receive terminal `key` input;
- custom cancellation still settles the dialog;
- stale target and disposal behavior from M2.1B remains unchanged.

### Compatibility Tests

The component matrix remains behavior-accurate:

- M2.1A adds adapter-contract evidence to every standard component.
- Behavior requirements remain `partial` or `planned` where M2.1C work is still missing.
- M2.1A does not change a component to `certification: "passing"` solely because its adapter closes.

- `getPiGuiAdapters()` returns only concrete adapters.

- `adapters.ts` contains no shape-probing identity helpers.
- `bridge.ts` discovers `Box` children through the adapter.
- `bridge.ts` does not probe unmarked components for standard `change`, `submit`, or `select` methods.
- Every standard adapter has snapshot evidence.
- Interactive adapter dispatch regressions remain green.
- Unknown custom components retain current terminal debug rendering and key dispatch.
- Compatibility status remains honest about M2.1C blockers.
- Focused, certification, renderer, and expanded test gates pass.
- Changed files have no TypeScript diagnostics.
- No code is committed by M2.1A subagents.
