# M2.1B Extension UI Lifecycle Closure Design

**Status:** Approved direction

**Date:** 2026-07-20

## Goal

Close the extension UI lifecycle gap without changing component behavior. A session runtime must own one authoritative extension UI snapshot, replay that snapshot to late or replacement renderer subscribers, terminate non-recoverable interactive requests when the runtime ends, and resolve extension flags through the same canonical session identity used by the runtime cache.

M2.1B is complete when renderer remount, session switching, path aliases, abort, owner disposal, and `/reload` all converge to deterministic state.

## Scope

This milestone covers:

- owner-side snapshots for `setStatus`, `setWidget`, `setHeader`, and `setFooter`;
- snapshot replay through the existing `session_state` event;
- renderer replacement semantics on every `session_state`;
- explicit termination of pending `confirm`, `select`, `input`, `editor`, and `custom` requests;
- in-memory handoff of recoverable UI state and compatible flag values across `/reload`;
- canonical session-path lookup for flag list and mutation;
- focused owner, IPC, and renderer reducer tests.

This milestone does not cover:

- persisting transient UI state to SQLite or JSONL;
- restoring extension UI after application restart when no live owner exists;
- replaying an interactive request into a replacement runtime;
- multi-request queues in the renderer;
- mature widget behavior, adapter replacement, or terminal fallback;
- extension enable/disable persistence or marketplace permissions.

## Current Failure Modes

The current event stream is sufficient only while one renderer remains subscribed continuously:

1. `AgentSessionRuntime` emits extension UI deltas but does not retain them in `getSessionState()`.
2. A late subscriber receives transcript, turns, queues, status, and rendered session entries, but not live statuses, widgets, header, or footer.
3. The renderer merges `session_state` only into `renderedEntries`, so stale UI from the previous session can survive a session switch.
4. Pending interactive requests live in the owner and are rejected on abort/dispose, but termination is not represented as a first-class lifecycle outcome.
5. `/reload` disposes the owner and rebuilds the extension runtime on the next send, losing recoverable UI and non-default flag values.
6. `listAgentFlagsForIpc`, `setAgentFlagForIpc`, shortcut routing, and extension-command routing can look up `sessionCache` with a renderer-supplied alias path even though the cache is keyed by the canonical real path.

## Ownership Model

### Session Runtime Is The Owner

`AgentSessionRuntime` remains the single owner for extension UI associated with a live session runtime. The renderer is a mirror and `ExtensionUiBridge` is only a late-binding transport seam.

The owner maintains:

```ts
export interface ExtensionUiSnapshot {
    statuses: Record<string, string>;
    widgets: Record<string, string[]>;
    widgetnodes: Record<string, WidgetNode>;
    header?: WidgetNode;
    footer?: WidgetNode;
}

export interface ExtensionReloadState {
    ui: ExtensionUiSnapshot;
    flags: Record<string, boolean | string>;
}
```

`AgentSessionRuntimeState` includes `extensionUi: ExtensionUiSnapshot`. `getSessionState()` returns defensive copies of all maps/records so callers cannot mutate owner state.

### Recoverable And Non-Recoverable State

| Surface | Owner stores it | Re-subscribe | `/reload` | App restart |
| --- | --- | --- | --- | --- |
| `notify` | No | No | No | No |
| status | Yes | Replay | Handoff | No |
| line widget | Yes | Replay | Handoff | No |
| semantic widget | Yes, serialized node only | Replay | Handoff | No |
| header/footer | Yes, serialized node only | Replay | Handoff | No |
| flag value | Runtime map + reload snapshot | Read canonically | Compatible handoff | No |
| interactive request | Pending promise only | Never replay | Terminate | Terminate |
| live widget target/component | `ExtensionUiBridge` only | Reused while owner lives | Dispose and rebuild | Dispose |
| rendered custom session entry | Session persistence | Re-render | Re-render | Re-render |

Serialized widget nodes are recoverable presentation state. Component instances, callbacks, `done` closures, target registrations, and request promises are runtime resources and must never cross owner replacement.

## Snapshot Mutation Contract

Every recoverable UI mutation follows one order:

1. Normalize the input into the owner snapshot.
2. Replace the affected owner record or field immutably.
3. Emit the existing `ext_ui_*` delta to current subscribers.

Specific rules:

- `setStatus(key, text)` sets `statuses[key]`; `null` or `undefined` deletes it.
- `setWidget(key, string[])` sets `widgets[key]` and deletes `widgetnodes[key]`.
- `setWidget(key, WidgetNode)` sets `widgetnodes[key]` and deletes `widgets[key]`.
- `setWidget(key, undefined)` deletes both representations.
- `setHeader` and `setFooter` replace or clear the corresponding field.
- `notify` emits only; it never mutates the snapshot.
- `requestUi`, `updateCustomWidget`, and `respondUi` operate only on the active request maps; they never mutate the recoverable snapshot.

One key can have either a line widget or a semantic widget, never both.

## Session Replay Contract

The existing `session_state` event is the only full-state replay envelope. Live owner snapshots add:

```ts
{
    type: "session_state",
    // existing conversation fields...
    extensionUi: {
        statuses,
        widgets,
        widgetnodes,
        header,
        footer,
    }
}
```

Replay rules:

1. `subscribeToOwner()` attaches the listener before reading the snapshot, preserving the current no-missed-delta ordering.
2. `sendLiveSessionState()` includes the owner's full extension UI snapshot.
3. `buildPersistedSessionState()` and `sendPersistedSessionState()` return an empty extension UI snapshot when no live owner exists.
4. The renderer treats `session_state.extensionUi` as replacement state, not a patch.
5. The renderer always clears `request` on `session_state`; requests are runtime-bound and absent from snapshots by design.
6. `renderedEntries` remains independently reconstructed from persisted session entries and is combined with the replacement extension UI state.

The replacement rule is load-bearing. It removes statuses, widgets, headers, footers, and requests left by a previously selected session instead of merging stale keys into the new session.

## Reload Handoff

`/reload` replaces the runtime but should not visually erase recoverable state before extensions have a chance to update it.

Before disposing the cached owner:

1. Capture `owner.getReloadState()`.
2. Move active renderer subscriptions to pending.
3. Terminate pending interactive requests with reason `reload`.
4. Dispose widget targets, extension lifecycle registrations, harness subscriptions, and the harness.
5. Store the captured state in a one-shot map keyed by canonical session path.
6. Remove all cache aliases for the old owner.

When the next send rebuilds the owner:

1. Consume and delete the one-shot reload state.
2. Seed `AgentSessionRuntime` with the UI snapshot.
3. Seed only flags still registered by the new extension graph and compatible with the new declaration type.
4. Keep new defaults for newly added, removed, or type-changed flags.
5. Attach pending subscribers and replay the rebuilt owner's complete `session_state`.

The one-shot state must be deleted after successful consumption and when session deletion or explicit cache teardown makes recovery impossible. It is process-memory continuity, not persistence.

## Request Termination

Interactive requests have exactly one terminal outcome:

- `resolved`: the renderer supplied a result or cancelled the prompt with `undefined`;
- `aborted`: the active agent operation was aborted;
- `reloaded`: the owner was replaced by `/reload`;
- `disposed`: the owner was otherwise destroyed.

Use a typed error so extensions and tests can distinguish lifecycle termination from extension failures:

```ts
export type ExtensionUiTerminationReason = "abort" | "reload" | "dispose";

export class ExtensionUiRequestTerminatedError extends Error {
    readonly code = "EXT_UI_REQUEST_TERMINATED";

    constructor(readonly reason: ExtensionUiTerminationReason) {
        super(`extension UI request terminated: ${reason}`);
    }
}
```

Owner teardown must:

1. atomically copy and clear `pendingUiRequests`;
2. clear `customWidgetRequestIds`;
3. unregister/dispose bridge widget targets;
4. reject every copied promise with one typed termination error;
5. make later renderer responses and widget events return no-op/`false`;
6. never invoke a stale `done` callback.

`abort` terminates pending requests but keeps recoverable UI. `/reload` and `dispose` terminate requests and dispose live component targets. Pending requests are not inserted into the reload handoff.

The renderer clears its request optimistically after a user response and authoritatively on the next `session_state`. No termination event is required for correctness because owner replacement temporarily detaches subscribers before disposal; the replacement snapshot is the convergence point.

## Canonical Flag Contract

The canonical session path returned by `validateSessionPath()` is the only key allowed for owner lookup and reload handoff.

All session-bound flag operations become asynchronous and follow:

```ts
const canonicalPath = await validateSessionPath(sessionMetadata.path, "sessionMetadata.path");
const owner = sessionCache.get(canonicalPath);
```

This applies to:

- `listAgentFlagsForIpc`;
- `setAgentFlagForIpc`;
- owner-backed extension command routing;
- owner-backed shortcut routing;
- any new session-bound extension IPC.

Flag state rules:

- The live extension runtime's `flagValues` map is authoritative while an owner exists.
- Headless discovery exposes declaration defaults only and never creates durable values.
- `setFlag` without a live canonical owner remains a no-op.
- Reload captures the old live values and restores only values whose new `RegisteredFlag.type` accepts the value.
- Boolean declarations accept only booleans; string declarations accept only strings.
- Removed flags are dropped; newly registered flags retain their new default.
- Duplicate flag-name behavior remains first-registration-wins in the IPC list surface.

Path aliasing must not create a second owner, a second reload state, or a second set of flag values.

## Bridge Disposal

`ExtensionUiBridge` gains an explicit idempotent `dispose()` operation:

```ts
export interface ExtensionUiBridge {
    attach(host: ExtensionUiHost): void;
    readonly host: ExtensionUiHost | undefined;
    registerWidgetRoot(...): () => void;
    dispatchWidgetEvent(event: WidgetEvent): boolean;
    dispose(): void;
}
```

`dispose()` clears the host, disposes each unique registered component target once, clears all targets, and makes dispatch return `false`. Per-root unregister callbacks remain idempotent after bridge disposal.

The owner calls bridge disposal only when the owner itself is replaced or destroyed, not on renderer unsubscribe. Renderer visibility must not control runtime lifetime.

## Ordering And Race Rules

- Owner state mutates before a delta is emitted.
- Subscription attaches before snapshot capture.
- A delta may arrive before or after the snapshot's asynchronous session-entry rendering; the renderer must still converge because the snapshot replaces recoverable state and later deltas patch it.
- Reload state is captured before request termination and bridge disposal.
- Reload state contains no requests or component instances.
- A renderer response racing with termination has one winner: deleting the request from `pendingUiRequests` is the linearization point.
- A stale response after termination is ignored.
- A stale widget event after bridge disposal returns `false`.
- Canonicalization completes before every owner lookup.

## Error Handling

- Invalid or out-of-root session paths continue to fail through `validateSessionPath()`.
- Snapshot replay failure logs the canonical session path and leaves the subscriber eligible for a later retry.
- Rejecting one pending request must not prevent remaining requests from being rejected.
- Widget disposal is best-effort per unique target; one adapter disposal failure must not leave the target map live.
- Reload-state seeding ignores incompatible values rather than coercing them.
- No lifecycle error is converted into a renderer toast unless an existing command result already surfaces it.

## Test Matrix

### Owner Tests

- Status, line widget, semantic widget, header, and footer mutate the snapshot before listener notification.
- Clearing a widget removes both representations.
- `getSessionState()` returns copies that cannot mutate owner state.
- Late subscribers receive a snapshot containing all recoverable UI.
- Abort rejects each request with reason `abort` and keeps recoverable state.
- Reload/dispose rejects each request with the correct reason and clears custom widget mappings.
- Stale responses and widget events are inert after teardown.
- Reload state contains UI and flags but no requests or live targets.

### IPC Tests

- A renderer subscribing through a symlink/alias path receives the canonical owner's UI snapshot.
- A persisted session without an owner returns an empty extension UI snapshot.
- `/reload` replays recoverable UI after owner rebuild and does not replay a request.
- Non-default compatible flags survive reload.
- Removed/type-changed flags do not survive reload.
- List/set flag operations work through a path alias and mutate only the canonical owner.
- Command and shortcut routing through an alias reaches the canonical owner.

### Renderer Tests

- `session_state` replaces statuses, widgets, widget nodes, header, footer, and rendered entries.
- `session_state` clears an active request.
- Subsequent deltas patch the replaced state.
- Switching from a populated session to an empty persisted session removes all prior extension UI.

## Acceptance Criteria

M2.1B is accepted when:

- one live owner exposes one authoritative extension UI snapshot;
- late subscribe and renderer remount reproduce the current recoverable UI;
- switching sessions cannot leak UI keys or requests from the previous session;
- abort, reload, and disposal settle every pending request exactly once;
- `/reload` restores recoverable UI and compatible non-default flags, but never restores requests or component instances;
- every session-bound flag lookup uses a validated canonical path;
- alias paths cannot fork owner or flag identity;
- focused tests pass under Node 22;
- the existing expanded M1/M2 regression suite remains green;
- repo-wide typecheck status is reported separately from this milestone's focused gate.
