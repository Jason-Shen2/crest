Architecture decision memo · 2026.07

Agent 架构需要去 Pane 化

固定 Agent Tab 改造改变了产品形态：用户面对的是一个 workspace 级 Agent 入口， 但代码仍用 pane 作为会话、运行时与 UI 的共同边界。核心 runtime 没错，错的是边界和名字还停留在旧模型。

建议重构，但不推倒 Session Runtime
01
保留 Session Owner 它是 transcript、turn、queue、status 与 extension lifecycle 的正确单一所有者。
02
替换 Pane 边界 UI 提升为 WorkspaceAgentSurface，main 侧提升为 AgentRuntimeRegistry。
03
分阶段迁移 先改名与收敛，再修生命周期，最后评估 hidden backing block。
00 / Context

产品已经变了，代码边界还没变

过去每个 Agent 都是一个可见 tab/pane；现在顶部只有一个固定 Agent 入口， 内部复用 hidden backing tab，并通过左侧 Session List 切换会话。这个改造是正确的产品方向， 但它让旧架构里的 pane 假设暴露出来。

Visible entry 固定 Agent Tab

用户只看到 workspace 级单一入口，不再把每个会话理解为一个 tab。

Compatibility carrier Hidden backing block

继续承载 TerminalModel、PTY、block meta 与工具上下文，暂时不直接移除。

Conversation identity Session path

真正的会话身份一直是 session path，而不是 tabId、blockId 或 pane。

New interaction 一个 Surface，多 Session

前台只展示 active session，其他 session 仍可在 main process 中运行。

01 / Problem

当前问题不是 runtime 错，而是三种身份被混在一起

UI surface、持久化 session、执行 runtime 本应是三个独立维度。 目前它们通过 hidden block 和 “Pane” 命名被绑在一起，导致生命周期、配置同步和扩展能力越来越难推理。

02 / Reframe

重构不是去掉 Session Runtime，而是让它脱离 pane

Session owner 是已经验证过的正确抽象。真正要做的是重新命名、重新划定 ownership， 并把 workspace UI、session execution、兼容 carrier 分开。

去 Pane 化，
不去 Runtime 化。

UI 是否可见，不应该决定 agent 是否继续运行；block 是否存在，也不应该决定 session 是否存在。 唯一稳定身份是 session path。

A Workspace Surface 只负责 activeSessionPath、assistant-ui、composer、session selector 和临时 UI 状态。
B Runtime Registry 负责按 session path 创建、复用、配置同步、订阅计数、后台运行与回收。
C Session Runtime 拥有一个 session 的 Harness、turn、queue、status、extensions 与 event fan-out。
D Compatibility Carrier hidden block 暂时仅提供 TerminalModel、PTY 与 block-scoped tools，不再是 Agent 身份。
Current Target Reason
PaneAgentSession → AgentSessionRuntime 它的身份和生命周期都属于 session path。
sessionCache → AgentRuntimeRegistry 从裸 Map 升级为有 lifecycle policy 的 owner。
AgentPane → WorkspaceAgentSurface 它是 workspace 级可见界面，不再对应可见 pane。
PaneHarness → AgentHarnessHost 它承载 mutable execution context，不应暗示 UI 所有权。
03 / Target

重构后：一个 Surface，多个独立 Runtime

切换 Session 只改变前台订阅对象，不销毁正在运行的任务。后台 session 可以继续执行， idle session 可以安全回收，并随时从持久化 repo 重建。

04 / Roadmap

四阶段重构，不做 Big Bang

先建立准确概念，再建立生命周期；先保证扩展与 observability 的接入点稳定， 最后才讨论彻底移除 hidden carrier。

Phase 01低风险 · 先做

改名与协议收敛

让代码名称与真实 ownership 一致，删除已经退化的 UI 过渡接口。

Change PaneAgentSession → AgentSessionRuntime

AgentPane → WorkspaceAgentSurface；清理 AgentSlot 常量字段和 19 个无用 deps。

Acceptance 行为零变化

现有 session、extensions、observability 与 assistant-ui 测试全部保持。

Phase 02核心价值

引入 Runtime Registry

把裸 Map 变成具有配置同步、引用计数和回收策略的明确 owner。

Change getOrCreate · syncConfig · release · evict

每次 send 前同步 model、reasoning、credentials、permissions 与 execution context。

Acceptance 前台切换不打断后台 run

idle runtime 可回收；running runtime 不回收；重新进入可从 repo 收敛状态。

Phase 03产品对齐

Workspace 状态成为 SSoT

active session 与 selection 从 block 身份中剥离，正式成为 workspace Agent 状态。

Change activeSessionPath 放入 workspace model

block meta 暂时保留为迁移镜像，避免破坏重启恢复与当前工具链。

Acceptance Session List 即导航

切换 session 只切换 surface subscription，不重新定义 Agent tab 或 pane。

Phase 04可选 · 最后评估

缩减或移除 Backing Block

只有当 TerminalModel、PTY 与 block-scoped tools 有替代宿主后，才继续去 carrier。

Change 抽出 AgentExecutionContext

显式提供 workspace cwd、connection、PTY host 与 tool target，而非借用 block。

Acceptance 无 block 仍可完整运行

shell/PTY 工具、extension UI、session 恢复与 focus 行为都具备新宿主。

01
不要先删 backing block

它仍承担 TerminalModel、PTY、block meta 和部分工具定位职责。先迁 ownership，再迁载体。

02
不要重写 AgentHarness

Harness 是正确内核，已有 model/reasoning setter、queue、session 与 extension hooks。

03
不要让 UI 持有 runtime

React surface 只镜像和发命令。后台任务生命周期必须由 main process registry 管理。

05 / Benefits

收益不是“名字更好听”，而是能力边界变清楚

去 Pane 化后，固定 Agent Tab、多 Session 并发、extension lifecycle、observability 和资源回收 会落在同一套可解释模型上。

01 / Correctness 模型选择与实际执行一致

每次 send 前由 Registry 同步配置，不再出现 UI 已切模型但旧 Harness 继续用旧模型。

02 / Concurrency 一个入口也能并行多个任务

Surface 只显示 active session；其他 session runtime 在 main 中独立继续运行。

03 / Lifecycle 资源可度量、可回收

running、subscribed、idle 三种状态有明确 policy，extensions 和 listeners 不再永久驻留。

04 / Extensibility Extension 绑定 Session，而非 UI

ctx.ui、flags、commands 与 widget request 的 owner 明确，切换前台不会破坏扩展运行时。

05 / Observability Trace 天然按 Runtime 聚合

sessionPath 与 turnId 成为稳定关联键，single、swimlane、race 不依赖 pane 是否存在。

06 / Maintainability 改 UI 不再触碰执行生命周期

Surface、Registry、Runtime、Repository 四个单元可独立测试、替换和演进。

06 / Decision

现在值得改，但只做前三阶段

Extension 与 Observability 正在继续加深对 session owner 的依赖。 越晚统一 ownership，后续改名和 lifecycle 修复的迁移面越大。

Recommended

现在启动 Phase 1–3

先做概念、Registry 和 workspace SSoT；保留 backing block 作为兼容 carrier。

  • 直接解决 cache、config drift 与 UI/runtime ownership
  • 为两个活跃 worktree 提供稳定接入点
  • 风险可通过阶段性测试和兼容镜像控制
Defer

暂缓 Phase 4

彻底移除 hidden block 的收益暂时小于 PTY、工具上下文和焦点系统迁移成本。

  • 不影响用户只看到一个固定 Agent 入口
  • 避免一次性重构 TerminalModel 与 block tools
  • 等 AgentExecutionContext 成熟后再做决策
Final call

保留已经正确的 Session Runtime；删除已经过时的 Pane 假设； 用 Registry 管理多个会话的执行生命周期，用 Workspace Surface 管理用户当前看到什么。
